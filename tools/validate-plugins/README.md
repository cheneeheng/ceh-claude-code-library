# validate-plugins

Repo-integrity checker for the `ceh-*` plugins. Stdlib-only Python — runs locally on any OS
and in CI with no install step. Used by `.github/workflows/validate.yml`.

```bash
python tools/validate-plugins/validate.py
```

Exits non-zero and prints a grouped list of problems if any check fails.

Check groups run in separate processes, using up to four workers, bounded by CPU count.
The report keeps the order in `CHECKS`. Hook fixtures use up to four isolated thread batches,
each with private temporary files and repositories. Fixtures from the same plugin or bare script
stay together and run in their original order, including repeats and callbacks. Failures retain
their original fixture numbering and report order.

On Windows, shell checks use Git Bash from the Git installation found through `git` on `PATH`.
They never fall back to WSL Bash. On macOS/Linux, they use `bash` on `PATH`. Both shell-check
groups print the selected executable. Missing Bash skips shell checks locally and fails in CI.

Run the runner's focused regression tests with
`python -m unittest discover -s tools/validate-plugins/tests -v`.

`validate.py` only runs the checks. Each group below is one module in `checks/`, listed in order in
`validate.py` (`CHECKS`, where `skill_refs` is the `skill-refs` group), and runs alone too:

```bash
python tools/validate-plugins/checks/skills.py
```

`checks/common.py` holds what the checks share: repo paths, the error collector, and the
frontmatter and manifest readers. A new check is a new module with a `check()` function, one line
in `CHECKS`, and a row below.

## Checks

| Group             | What it verifies                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `manifests`       | Each `plugins/*/ceh-*/.claude-plugin/plugin.json` is valid JSON, `name` matches its directory, `version` is semver. `marketplace.json` lists every plugin with a matching version and an existing `source` path; no plugin is missing or unlisted.                                                                                                                                                                                                                                                                                                                                                                                                             |
| `skills`          | Every `skills/<name>/SKILL.md` has `name` + `description` frontmatter and `name` matches the directory. `description` ≤ 300 chars (the skill listing drops whole descriptions once it overflows its budget), `compatibility` ≤ 500. `disable-model-invocation`, `user-invocable`, and `license` are stated explicitly.                                                                                                                                                                                                                                                                                                                                         |
| `agents`          | Every `agents/<name>.md` has `name` + `description` + `model` frontmatter and `name` matches the file name. `description` ≤ 300 chars.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `keys`            | Names are lowercase-hyphenated, ≤ 64 chars. Every frontmatter key is one the Claude Code docs define; keys Claude Code ignores on plugin agents (`permissionMode`, `hooks`, `mcpServers`, `initialPrompt`) fail. No `TEMPLATE-GUIDANCE` comment is left over from a template.                                                                                                                                                                                                                                                                                                                                                                                  |
| `scalars`         | `description` uses the folded block scalar `>-`; no other key is an unquoted scalar containing `: `.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `references`      | `references/...`, `${CLAUDE_PLUGIN_ROOT}/{scripts,references}/...` and `${CLAUDE_SKILL_DIR}/...` mentions in skill/agent files, and `../assets/...` or `../references/...` mentions in reference files, resolve to a real file.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `budget`          | The sum of every skill and agent description stays under `MAX_TOTAL_DESCRIPTION_LEN`, a ratchet: lower it when the total drops, raise it only in the PR that adds a component, by that component's description length.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `skill-refs`      | `plugin:component` references in skills, agents, and output styles resolve to an existing skill or agent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `retired-names`   | No file names a retired plugin, bare or as `plugin:component`: a name with a folder under `archive/` and no live plugin, or a key of `RENAMED`. It reads root `*.md` files, text files under `plugins/`, `docs/`, `tools/`, `.claude/`, `.github/`, and `examples/`, and `marketplace.json`, and skips `CHANGELOG.md`, `product/`, `audits/`, and `archive/`, which are records. A file that states history on purpose is listed for that name in `ALLOWED`.                                                                                                                                                                                                   |
| `deps`            | Every `dependencies` entry names a plugin in this repo, and the graph is acyclic.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `invocations`     | Every `Invoke the Skill tool with skill="X"` resolves, is in-plugin or in a declared dependency, and does not set `disable-model-invocation: true`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `repo-rules`      | `docs/PLUGIN_VERSIONS.md` matches every `plugin.json` version; each plugin's newest `CHANGELOG.md` Plugin versions row matches it too, under the date `PLUGIN_VERSIONS.md` gives it; no `marketplace.json` entry declares `dependencies`; a cross-cutting plugin (the `CLAUDE.md` tier table) depends only on cross-cutting plugins; a skill a hook script names sets `user-invocable: false`; every user-only skill is named in `ceh-every-session:whats-next`.                                                                                                                                                                                               |
| `registry`        | Every line of the `find-available-guide` registry has eight non-empty cells, a known kind and method, an `https://` source, a real past `checked` date, and no repeated name and install pair.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `hygiene`         | Tracked or new files git does not ignore, among root `*.md` files and text files under `plugins/`, `docs/`, `tools/`, `.claude/`, `.github/`, `product/`, `audits/`, and `examples/` hold no invisible Unicode (zero-width, bidi, BOM) and no personal absolute path (a Windows or macOS `Users` folder, a Linux `home` folder, or the `C--Users-<name>` folder name Claude Code gives a project). Every skill and agent on disk is named in backticks in its plugin `README.md`.                                                                                                                                                                              |
| `scripts`         | `*.sh` pass `bash -n` (and `shellcheck` when available); `*.py` pass `py_compile`, in a plugin's `scripts/` and each skill's `scripts/`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `hooks`           | Every script a `hooks.json` runs has fixtures in `checks/hooks.py`. Each fixture pipes a hand-built payload into the script and checks its exit code and output. No model call.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `templates`       | Every `*.template.md` sits in an `assets/` folder, opens with `schema: <its file name>/v<N>` as its first frontmatter key, and is cited by a file in its plugin. It holds no explanation: no frontmatter `# comment`, no `<!--` comment, and no placeholder over 30 characters unless it is an `a \| b` choice. Its schema, `references/<name>-schema.md` beside the `assets/` folder, names the template and is cited by another file in the plugin. A skill whose `## Output` names a saved `.agents_workspace/` or `product/` file cites a template.                                                                                                        |
| `artifact-models` | Each YAML format's `references/<name>-model.py` has `<name>-schema.md` beside it and `../assets/<name>.template.yaml`, and its plugin ships `scripts/artifact.py` and both artifact hooks. With `uv`, `model_vs_template.py` also checks that each template's keys, nested lists included, are exactly its model's, and each `product/plans/*.yaml` passes `artifact.py check`, so its generated Markdown is not stale.                                                                                                                                                                                                                                        |
| `copies`          | Every whole-file copy `docs/CROSS_REFERENCES.md` registers (Section `whole file`, Diverges `none`, one full path per row) is byte-identical to the canonical file of the same name on its entry's Canonical line. It fails drift, a registered path that does not exist, a row it cannot pair, and two identical files at the same path in different skill folders that no registered pair links; same-name files that differ pass. It also fails a plugin root holding `assets/` or `references/`, a skill or agent citing `${CLAUDE_PLUGIN_ROOT}/assets/` or `/references/`, and a skill's reference file naming `${CLAUDE_PLUGIN_ROOT}` or `<plugin root>`. |

`shellcheck` is used when present and skipped otherwise. Bash checks skip locally when Bash is
missing and fail in CI, where GitHub-hosted Ubuntu runners ship both tools. `uv` is
treated the same way locally, for the artifact hook fixtures and the template comparison, but CI
installs it, and `hooks` and `artifact-models` fail there when it is missing.
