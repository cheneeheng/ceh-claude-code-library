# Schema real example

Before designing a schema for a kind of content, read a real example the user has (such as a spec with routes, data models and nested rules) and test the shape against it before planning and building, because the first `technical_design` shape merged in PR #365 could not hold real contract content and a second plan and PR #367 were needed.
