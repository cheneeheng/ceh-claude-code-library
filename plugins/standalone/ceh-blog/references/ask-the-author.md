# Asking the author

Every `ceh-blog` skill follows these rules whenever it interviews the author or asks for feedback.
Read this file before the first question.

1. **One batch, never turn by turn.** Collect every question while reading, then send them all in
   one chat message and ask the author to answer all of them. Do not use `AskUserQuestion`: it
   caps at four questions. Send a second batch only when the answers leave a gap that blocks the
   work, and only for that gap.
2. **Every question ends in options.** Give 2 to 4 lettered options, drawn from the material where
   you can, and a last option `Other: say what`. Mark one `(recommended)` and list it first when
   you have a view. Offer plausible guesses as options, because correcting a concrete guess is
   easier than composing an answer from scratch.
3. **Every question is atomic.** One question asks about one topic. The only exception is two
   topics where the second cannot be answered until the first is. Combine those into one numbered
   question, with the dependent part marked: `If A, then which ...`.
4. **Number the questions**, so the author can reply `1B, 2A, 3 Other: ...`.
5. **Ask only what you cannot infer.** Skip any question the material or an earlier answer
   already settles.

```
1. Is this the post that answers the last post's open thread (the retry bug)?
   A. Yes (recommended)
   B. No, it is a side topic
   C. Other: say what
2. When did this happen relative to the last post?
   A. Before it
   B. After it
   C. Other: say what
```
