# ceh-competitor-analysis design notes

Maintainer detail moved out of the plugin README on 2026-11-24, when the README was rewritten for
the person installing the plugin. The site does not publish this file.

## Report page rendering

Each report is then rendered as an HTML page by `scripts/render-page.py`, which fills the plugin's
page template from the YAML and links every page in the folder from its nav, with the theme from
`ceh-ui-design:design-ui`.

The YAML is the source of each report, and `comparison.md` the source of the comparison; the HTML
pages carry the same content, built from each skill's `assets/report-page.html`, with detail folded
into expandable cards. A competitor page is generated by `render-page.py` and never edited by hand,
and the comparison page is still built by hand. Reports written before `v2` stay as
`<competitor>.md`, which the comparison still reads.

The report YAML is `competitor-report/v2`, checked by a model.

## Why the analyst runs as a subagent

Running it in a subagent keeps a large repo's files out of the main session, and lets several
competitors be read at once.

## Hook wiring

Two hooks on `Edit|Write|MultiEdit`, both Python scripts that need `python3` on `PATH`:

- `artifact-render-hook.py` (PostToolUse) checks a written competitor report YAML against its
  model and renders its Markdown. The check needs `uv`; without it the agent is told once per
  session that the report went unchecked.
- `generated-md-guard.py` (PreToolUse) denies a hand edit to the generated Markdown, which the
  next render would overwrite.

`CEH_ARTIFACT_CHECK=off` turns both off, and `CEH_DISABLED_HOOKS` turns off either by name.
